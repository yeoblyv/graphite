# Security Policy

## Supported versions

Only the latest tagged release receives security fixes. There is no
long-term-support branch at this project's current scale — upgrading to
the latest tag is the supported remediation path for any reported issue.

## Reporting a vulnerability

Report a suspected vulnerability privately, not as a public issue or pull
request:

- Email: **xineraman8@gmail.com**

Include what you found, the affected version/commit, and, if possible, a
minimal reproduction. Expect an acknowledgment within 5 business days.

Do not open a public issue, pull request, or discussion describing the
vulnerability before a fix has shipped — early disclosure puts users of
the affected version at risk while no fix exists yet.

## Disclosure process

Once a report is confirmed, a fix is prepared and released, and the
`CHANGELOG.md` entry for that release describes the issue — only after
the patched version is available, never before. The reporter is credited
in that entry unless they ask not to be.
